# aws-k8s-platform

Kubernetes and AWS deployment for two of my Spring Boot services, using plain Kubernetes YAML, `kubectl`, Docker and the AWS CLI:

- [payflow-ledger](https://github.com/Jagadeesh-Udatha/payflow-ledger): payments ledger on MySQL + Kafka (transactional outbox)
- [telemetry-stream](https://github.com/Jagadeesh-Udatha/telemetry-stream): vehicle GPS stream processing on Kafka + MongoDB

Every push runs CI, which creates a real kind cluster, deploys MySQL, Kafka, MongoDB and both services with `kubectl apply`, and runs an end-to-end smoke test.

```
 GitHub Actions ──OIDC──▶ IAM role ──▶ aws/deploy.sh: docker build ─▶ ECR ─▶ kubectl apply + set image + rollout status
                                                                           │
 ┌──────────────────────── VPC (eksctl, 2 AZs) ────────────────────────────┼─────────────┐
 │  EKS managed node group (private subnets)                               ▼             │
 │    ├─ payflow-ledger    Deployment · Service (LoadBalancer) · HPA · PDB                │
 │    └─ telemetry-stream  Deployment · Service (LoadBalancer) · HPA · PDB                │
 │  RDS for MySQL 8.4 (private)       Amazon MSK (Kafka, 2 brokers)                       │
 └────────────────────────────────────────────────────────────────────────────────────────┘
 AWS Secrets Manager: platform-dev/payflow-ledger, platform-dev/telemetry-stream   ·   MongoDB Atlas for telemetry
```

## Layout

| Path | What it is |
|---|---|
| `k8s/<app>/` | Plain manifests per service: Deployment, Service, HorizontalPodAutoscaler, PodDisruptionBudget. |
| `k8s/namespace.yaml` | The `platform` namespace. |
| `dev/` | kind cluster config, in-cluster MySQL/Kafka/MongoDB (`deps.yaml`), `up.sh` (deploy) and `smoke.sh` (end-to-end test). |
| `aws/cluster.yaml` | EKS cluster for `eksctl` (VPC, managed node group, metrics-server). |
| `aws/create.sh` | One-time AWS setup with the AWS CLI: EKS, ECR, RDS for MySQL, MSK, Secrets Manager. |
| `aws/deploy.sh` | Build + push one service to ECR and roll it out on EKS. |
| `aws/destroy.sh` | Deletes everything `create.sh` made. |
| `.github/workflows` | `ci.yml` (kubeconform, shellcheck, kind e2e) and `deploy.yml` (manual deploy to EKS). |

## What the manifests do for a Spring Boot pod

- Startup, liveness and readiness probes on `/actuator/health/*`; the startup probe gives a slow JVM start up to 2 minutes.
- Zero-downtime rollouts: `maxUnavailable: 0`, readiness gates traffic, a `preStop` sleep lets the load balancer stop routing before Spring's graceful shutdown drains requests.
- Runs as non-root user 10001 with a read-only root filesystem (writable `/tmp` only), all capabilities dropped and the RuntimeDefault seccomp profile.
- Config from a ConfigMap and credentials from a Secret, both loaded with `envFrom`; nothing sensitive is in git.
- HPA on CPU 70% (2-6 pods) and a PDB that keeps one pod up during node drains; pods spread across zones.

## Run it locally (kind)

Needs Docker, kind, kubectl and jq.

```bash
kind create cluster --config dev/kind.yaml
docker build -t payflow-ledger:ci ../payflow-ledger && kind load docker-image payflow-ledger:ci --name platform
docker build -t telemetry-stream:ci ../telemetry-stream && kind load docker-image telemetry-stream:ci --name platform
./dev/up.sh      # MySQL, Kafka, MongoDB, then both services with kubectl apply
./dev/smoke.sh   # transfer + idempotent replay + Kafka event; GPS event -> overspeed alert
```

## Deploy to AWS

> **Cost warning.** This creates billable resources: the EKS control plane (about $0.10/hour), nodes, a NAT gateway, RDS and MSK. Run `aws/destroy.sh` when you're done.

Needs the AWS CLI (logged in), eksctl, kubectl, Docker and jq.

```bash
aws/create.sh                                   # 30-45 minutes; asks for the MongoDB Atlas URI at the end
aws/deploy.sh payflow-ledger ../payflow-ledger
aws/deploy.sh telemetry-stream ../telemetry-stream
aws/destroy.sh
```

To deploy from GitHub instead, create an IAM role that trusts GitHub's OIDC provider for this repository (`repo:Jagadeesh-Udatha/aws-k8s-platform:environment:dev`), allow it to push to the two ECR repositories, read the two secrets and edit the `platform` namespace (EKS access entry), then set its ARN as the repository variable `AWS_DEPLOY_ROLE_ARN` and run the **Deploy** workflow.

## Security choices

- No AWS keys in GitHub: Actions log in through OIDC.
- Database and Kafka are in private subnets and accept connections only from the EKS cluster security group.
- Passwords are generated by `create.sh`, stored in Secrets Manager and copied into a Kubernetes Secret at deploy time.
- ECR tags are immutable (the tag is the git SHA) and images are scanned on push.

## Known limits

- MSK uses plaintext inside the VPC; the next step is TLS + IAM auth.
- Secrets are copied into Kubernetes at deploy time, so a rotated password needs a redeploy.
- The AWS scripts are checked with shellcheck in CI but not run from CI (to avoid AWS costs). The kind path is deployed and tested on every push.
